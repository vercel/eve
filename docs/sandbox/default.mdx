---
title: "Default Sandbox"
description: "Let eve select the sandbox provider for the current environment."
---

`DefaultSandbox.environment()` selects a sandbox provider when eve prepares the sandbox, records the choice, and uses that provider for every session the build serves.

```ts
import { DefaultSandbox, defineSandbox } from "eve/sandbox";

export const environment = DefaultSandbox.environment();
export default defineSandbox(() => environment.open());
```

## How eve selects the provider

eve checks the environment in this order when it prepares the sandbox:

| Where eve prepares the sandbox                    | Selected provider                             |
| ------------------------------------------------- | --------------------------------------------- |
| On Vercel (`vercel build` or a Vercel deploy)     | [Vercel Sandbox](/docs/sandbox/vercel)        |
| Anywhere a Linux Docker daemon is reachable       | [Docker](/docs/sandbox/docker)                |
| `eve dev` or `eve eval` without Docker            | [just-bash](/docs/sandbox/just-bash)          |
| A production `eve build` without Vercel or Docker | None: opening the sandbox fails with an error |

Production builds never fall back to just-bash, because just-bash runs no native processes and provides no network isolation. When no provider is available, `eve build` still succeeds and logs that no provider is available. The first session that opens the sandbox fails with an error that asks you to start Docker and rebuild, deploy to Vercel, or select a provider explicitly in your sandbox module.

## The build records the choice

`eve build` prepares the sandbox and stores the selected provider in the build's prepared sandbox artifact. `eve dev` prepares it the first time a session opens the sandbox. At runtime, `DefaultSandbox` reads the recorded provider and does not probe for Vercel or Docker again, so the build and the server it produces always use the same provider. To change the provider, rebuild in an environment where the provider you want is available.

Each session also records the provider it started with. If a later build selects a different provider, a session that resumes on the new build starts a fresh sandbox from the new provider, without the old sandbox's files. eve does not delete the old sandbox: a Vercel Sandbox stays in your Vercel project, and a Docker container stays on the Docker host until you remove it.

## Configure each provider

Pass provider-specific environment options under `vercel`, `docker`, or `justBash`. eve applies only the options for the selected provider. A top-level `prepare` callback runs for every provider:

```ts
import { DefaultSandbox, defineSandbox } from "eve/sandbox";

export const environment = DefaultSandbox.environment({
  docker: { image: "ghcr.io/acme/agent-sandbox:latest" },
  prepare: async (sandbox) => {
    await sandbox.run({ command: "mkdir -p data/cache" });
  },
  vercel: { resources: { vcpus: 4 } },
});

export default defineSandbox(() => environment.open());
```

## Network policy

Pass `networkPolicy` to `open()` or call `setNetworkPolicy()` on the session. eve forwards the policy to the selected provider:

```ts
import { DefaultSandbox, defineSandbox } from "eve/sandbox";

export const environment = DefaultSandbox.environment();
export default defineSandbox(() => environment.open({ networkPolicy: "deny-all" }));
```

Vercel Sandbox accepts every network policy, including domain allow-lists and credential transforms. Docker accepts only `"allow-all"` and `"deny-all"`. just-bash always allows network access, so it accepts only `"allow-all"` and rejects any other policy with an error. Use [Vercel Sandbox](/docs/sandbox/vercel) directly when you need domain-level policies in every environment.

Use a provider directly when you need its image, compute, or mount options at `open()`.
