Most projects have one root agent: the agent that receives requests through its own HTTP endpoint. Choose an agent workspace when several root agents need their own endpoints, channels, schedules, or ownership boundaries. Choose declared subagents when one root agent needs to delegate specialized work.

## Choose the agent boundary

| Need                                                                                            | Use                                                       |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| One public agent with several tools, skills, channels, or subagents                             | One root agent                                            |
| A specialist with a different prompt, tool surface, or sandbox that the root agent delegates to | A declared subagent under `agent/subagents/`              |
| Agents independently addressed through their own endpoints, channels, or schedules              | Multiple root agents in an agent workspace                |
| An agent owned or released independently                                                        | A separate root agent, in this project or another project |

Each root agent has its own HTTP surface and lifecycle. A declared subagent is a tool of its parent agent, so users and channels cannot address it directly. See [Subagents](../subagents) for delegation, or [Remote Agents](../guides/remote-agents) when a subagent runs in another deployment.

## Choose a root-agent layout

A project with one root agent has an `agent/` directory at its root:

```text
my-agent/
├── package.json
├── agent/
│   ├── instructions.md
│   ├── tools/
│   ├── skills/
│   └── subagents/
└── evals/
```

An agent workspace keeps each independently addressed root agent under `agents/<name>/`:

```text
operations/
├── package.json
├── tsconfig.json
└── agents/
    ├── support/
    │   └── agent/
    │       ├── instructions.md
    │       ├── tools/
    │       └── channels/
    └── research/
        └── agent/
            ├── instructions.md
            ├── tools/
            └── channels/
```

Each workspace member uses the same [agent directory layout](./#agent-directory-layout) as a standalone root agent. They share the root package, dependencies, and build scripts. If `agents/<name>/` has its own `package.json`, it is a separate package rather than a workspace member.

## Create an agent workspace

Pass comma-separated agent names to `eve init`:

```bash
eve init operations --agents support,research
```

To add another root agent later, run `eve init <name>` from the workspace root:

```bash
cd operations
eve init billing
```

This adds `agents/billing/agent/`. Run agent-scoped commands from that member directory, or select the agent from the workspace root with `--agent`:

```bash
eve info --agent billing
```

When you run an interactive agent-scoped command without naming an agent, eve offers a picker.
