---
title: "Multi-Agent Projects"
description: "Organize several independently addressed eve root agents in one project."
---

A multi-agent project contains several independently addressed root agents. Use one when agents need separate public endpoints, channels, schedules, deployments, or ownership boundaries. For specialized work delegated by one root agent, use [declared subagents](./subagents) instead.

## Decide whether you need multiple root agents

Start with one root agent unless you need an independent boundary.

| Need                                                                                          | Use                                          |
| --------------------------------------------------------------------------------------------- | -------------------------------------------- |
| A specialist with a different prompt, tool surface, or sandbox that a root agent delegates to | A declared subagent under `agent/subagents/` |
| One public agent with several tools, skills, channels, or subagents                           | A single-agent project                       |
| Agents with separate public endpoints, channels, schedules, or deployments                    | A multi-agent project                        |
| Agents owned or released independently                                                        | A multi-agent project                        |

A root agent has its own HTTP surface and lifecycle. A declared subagent is a tool of its parent agent and is not independently addressed by users or channels.

## Create a multi-agent project

Pass comma-separated agent names to `eve init`:

```bash
eve init operations --agents support,research
```

This creates a project with one root package and one agent directory for each name:

```text
operations/
├── package.json
├── tsconfig.json
└── agents/
    ├── support/
    │   └── agent/
    │       ├── agent.ts
    │       ├── instructions.md
    │       └── channels/
    └── research/
        └── agent/
            ├── agent.ts
            ├── instructions.md
            └── channels/
```

Workspace members share the root package, dependencies, and build scripts. An `agents/<name>/` directory with its own `package.json` is a separate package, not a workspace member. Each member can use the same [agent directory layout](./getting-started#agent-directory-layout) as a standalone root agent.

## Add another root agent

Run `eve init <name>` from the workspace root:

```bash
cd operations
eve init billing
```

The command adds `agents/billing/agent/`. Run an agent-scoped command from that member directory, or select it from the workspace root with `--agent`:

```bash
eve info --agent billing
```

Interactive agent-scoped commands offer a picker when a workspace has several agents and you do not name one.

## Develop and deploy the workspace

Develop one workspace member at a time. Run `eve dev` from its directory, or select it from the workspace root:

```bash
eve dev --agent support
```

On Vercel, a workspace member is available at `/<name>/eve/v1/*`, such as `/support/eve/v1/health`. Run project-level build, link, and deploy commands from the workspace root. See [Deploy to Vercel](./guides/deployment/vercel#deploy-the-agent) for the generated service and route behavior.

When one workspace agent calls another, declare the peer as a [workspace subagent](./subagents#vercel-workspace-peers). Outside Vercel, configure an explicit [remote-agent transport](./guides/remote-agents).

## Add a web app

A web app is optional and separate from the workspace decision. To add a browser UI to a single-agent project or connect an existing frontend, see [Add a Web App](./guides/frontend/add-a-web-app).

Web Chat cannot currently be installed directly into an `agents/` workspace with `eve add channel/web`. Configure a root Next.js app with `withEve({ agents })` manually instead. See [Next.js](./guides/frontend/nextjs) for the multi-agent configuration.
