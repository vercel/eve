Dynamic workflows let the root agent run one model-authored JavaScript program that coordinates child-agent calls and returns one JSON-serializable result. Add the `workflow` tool when the model needs loops, fan-out, dependent calls, filtering, or aggregation across subagents.

The model-facing `workflow` tool is distinct from both:

- [`defineWorkflowTool`](./workflows), which authors a named tool whose implementation you write and run with the Workflow SDK.
- `experimental.workflow`, which configures the Workflow SDK runtime used by eve, including its world, checkpoint batching, and retention.

## Enable dynamic workflows

Create `agent/tools/workflow.ts` and export the default tool:

```ts title="agent/tools/workflow.ts"
export { default } from "eve/tools/workflow";
```

The default allows up to `100` subagent calls in one program. Import the factory to set a different limit:

```ts title="agent/tools/workflow.ts"
import { workflow } from "eve/tools/workflow";

export default workflow({ maxSubagents: 20 });
```

`maxSubagents` must be a positive integer. Parallel and sequential calls count toward the same per-program limit. A call over the limit fails with `WORKFLOW_SUBAGENT_LIMIT_REACHED` and does not start a child. Remove `agent/tools/workflow.ts` to remove the tool.

The `workflow` tool is available only in a root session and only when at least one subagent is visible for the current model step. Runtime subagent sessions do not receive it.

## Available capabilities

A dynamic workflow program is subagent-only: it can call only the subagents listed in the `workflow` tool description. This can include the built-in `agent` child, declared subagents, remote subagents, and subagents selected by [`defineDynamic`](../guides/dynamic-capabilities) when they are visible for that model step.

The program cannot directly call ordinary authored or built-in tools. Search and describe helpers, connections, approvals, authentication helpers, and session state are also unavailable inside the program. A called subagent still runs with its own configured capabilities.

Enabling `workflow` does not remove or wrap the root's direct subagent tools. The model can still call those tools directly for fixed delegation. Direct calls run in the background and return task receipts. Calls made inside `workflow` wait for each child's final result, so the program can use the returned values in later calls or in its final result.

## Build a multi-stage pipeline

The model writes the `js` body when it calls `workflow`. For example, a software-factory agent can manufacture 200 test tickets, triage the full batch, review the triage report, and produce a reproduction test artifact:

```js
const tickets = Array.from({ length: 200 }, (_, index) => ({
  id: `T-${String(index).padStart(3, "0")}`,
  area: ["api", "cli", "runtime", "docs"][index % 4],
  severity: ["critical", "high", "medium", "low"][index % 4],
  title: `Synthetic regression ${index}`,
}));

const triage = await tools["ticket-triage"]({
  message: JSON.stringify({ stage: "triage", tickets }),
  outputSchema: {
    type: "object",
    properties: {
      ticketCount: { type: "integer" },
      priorityTickets: { type: "array", items: { type: "string" } },
      themes: { type: "array", items: { type: "string" } },
    },
    required: ["ticketCount", "priorityTickets", "themes"],
    additionalProperties: false,
  },
});

const review = await tools["ticket-review"]({
  message: JSON.stringify({ stage: "review", triage }),
  outputSchema: {
    type: "object",
    properties: {
      accepted: { type: "boolean" },
      summary: { type: "string" },
      risks: { type: "array", items: { type: "string" } },
    },
    required: ["accepted", "summary", "risks"],
    additionalProperties: false,
  },
});

const reproduction = await tools["ticket-reproducer"]({
  message: JSON.stringify({ stage: "reproduce", triage, review }),
  outputSchema: {
    type: "object",
    properties: {
      sampleTicket: { type: "string" },
      files: { type: "array", items: { type: "string" } },
      command: { type: "string" },
      testCase: { type: "string" },
    },
    required: ["sampleTicket", "files", "command", "testCase"],
    additionalProperties: false,
  },
});

return { triage, review, reproduction };
```

Each `await` creates a stage boundary. The review call cannot start until triage returns, and the reproduction call receives both prior results. Use `Promise.all` instead when stages are independent and can run concurrently.

## Continue a child

Each subagent call accepts the same input fields as direct delegation:

```ts
{
  message: string;
  agentId?: string;
  outputSchema?: object;
}
```

Pass a known `agentId` to the same subagent to continue or steer that child. Omitting `agentId` starts a new child. Every call, including a continuation, counts toward `maxSubagents`.

For the full child-session lifecycle and `agentId` behavior, see [Subagents](../subagents).
