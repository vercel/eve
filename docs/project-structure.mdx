description: "Choose a single root agent, an agent workspace, or declared subagents before you create a project."
---

Choose the project structure before creating your agent. Most projects have one root agent. Use an agent workspace when several root agents need their own public endpoints, channels, schedules, or ownership boundaries. Use declared subagents when one root agent delegates specialized work.

## Choose the agent boundary

| Need                                                                                            | Use                                                       |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| One public agent with several tools, skills, channels, or subagents                             | One root agent                                            |
| A specialist with a different prompt, tool surface, or sandbox that the root agent delegates to | A declared subagent under `agent/subagents/`              |
| Agents independently addressed through their own endpoints, channels, or schedules              | Multiple root agents in an agent workspace                |
| An agent owned or released independently                                                        | A separate root agent, in this project or another project |

A root agent has its own HTTP surface and lifecycle. A declared subagent is a tool of its parent agent and is not independently addressed by users or channels. See [Subagents](./subagents) for delegation and [Remote Agents](./guides/remote-agents) when a subagent runs in another deployment.

## Choose a root-agent layout

A project with one root agent has an `agent/` directory at its root:

```text
my-agent/
├── package.json
├── agent/
│   ├── instructions.md
│   ├── tools/
│   ├── skills/
│   └── subagents/
└── evals/
```

An agent workspace keeps each independently addressed root agent under `agents/<name>/`:

```text
operations/
├── package.json
├── tsconfig.json
└── agents/
    ├── support/
    │   └── agent/
    │       ├── instructions.md
    │       ├── tools/
    │       └── channels/
    └── research/
        └── agent/
            ├── instructions.md
            ├── tools/
            └── channels/
```

Each workspace member uses the same [agent directory layout](./getting-started#agent-directory-layout) as a standalone root agent. Workspace members share the root package, dependencies, and build scripts. An `agents/<name>/` directory with its own `package.json` is a separate package, not a workspace member.

## Create an agent workspace

Pass comma-separated agent names to `eve init`:

```bash
eve init operations --agents support,research
```

To add another root agent later, run `eve init <name>` from the workspace root:

```bash
cd operations
eve init billing
```

The command adds `agents/billing/agent/`. Run an agent-scoped command from that member directory, or select it from the workspace root with `--agent`:

```bash
eve info --agent billing
```

Interactive agent-scoped commands offer a picker when a workspace has several agents and you do not name one.
