`useEveAgent()` from `eve/vue` exposes the shared eve frontend client as Vue computed refs and methods. See the [frontend overview](./overview) for session behavior, messages, human input, authorization, callbacks, and persistence.

In Nuxt, the [`eve/nuxt` module](./nuxt) auto-imports the composable.

## Basic usage

Import the composable from `eve/vue`. Its state is exposed as `ComputedRef`s, so templates unwrap it automatically:

```vue
<script setup lang="ts">
import { useEveAgent } from "eve/vue";
import { computed, ref } from "vue";

const { messages, status, send } = useEveAgent();
const message = ref("");
const isBusy = computed(() => status.value === "busy");
const isInputDisabled = computed(() => isBusy.value || status.value === "resuming");

async function handleSubmit() {
  const text = message.value.trim();
  if (!text || isInputDisabled.value) return;
  message.value = "";
  await send(text);
}
</script>

<template>
  <div v-for="item in messages" :key="item.id">
    <p>{{ item.role }}: {{ item.parts }}</p>
  </div>
  <form @submit.prevent="handleSubmit">
    <input v-model="message" :disabled="isInputDisabled" />
    <button type="submit" :disabled="isInputDisabled">Send</button>
  </form>
</template>
```

## What it returns

The state fields are computed refs; the commands are ordinary methods:

| Property                                                                                            | Vue shape                                      |
| --------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `messages`, `agents`                                                                                | Computed refs for the snapshot fields          |
| `view`                                                                                              | `ComputedRef<SessionView>`                     |
| `status`                                                                                            | `ComputedRef<UseEveAgentStatus>`               |
| `error`                                                                                             | `ComputedRef<Error \| undefined>`              |
| `events`                                                                                            | `ComputedRef<readonly SessionStreamEvent[]>`   |
| `session`                                                                                           | `ComputedRef<ClientSessionState \| undefined>` |
| `send`, `respond`, `prewarm`, `resume`, `follow`, `cancel`, `clear`, `compact`, `end`, `newSession` | Methods                                        |

Destructuring preserves reactivity because each state value remains a ref. Read refs with `.value` in `<script>` and without `.value` in a template. The [`useEveAgent` reference](./use-eve-agent#returned-state) describes what each value and command does.

## Send a message

Call `send(text)` for text or pass content parts for attachments. The API and streaming behavior match the [sending reference](./use-eve-agent#sending). `send()` and `respond()` resolve with a `Delivery` receipt when the server accepts the request, before the agent finishes. Read the receipt's `sessionId` and `deliveryId`, or use its [`stream()` and `result()` reads](../client/messages#reusable-delivery-reads).

## Human-in-the-loop prompts

Read requests from the shared `view` and answer them with `respond()`. A request stays open until `interaction.settled`, even after you submit an answer.

```vue
<script setup lang="ts">
import { computed } from "vue";
import { openInteractions } from "eve/events";
import { useEveAgent } from "eve/vue";

const { view, status, respond } = useEveAgent();
const pendingRequests = computed(() =>
  openInteractions(view.value).filter(
    (item) => item.request.kind !== "sign-in" && item.answer === undefined,
  ),
);
</script>

<template>
  <fieldset
    v-for="item in pendingRequests"
    :key="item.interactionId"
    :disabled="status === 'resuming'"
  >
    <legend>{{ item.request.prompt }}</legend>
    <button
      v-for="option in item.request.options ?? []"
      :key="option.id"
      type="button"
      @click="respond([{ interactionId: item.interactionId, optionId: option.id }])"
    >
      {{ option.label }}
    </button>
  </fieldset>
</template>
```

See [Human-in-the-loop prompts](./overview#human-in-the-loop-prompts) for request semantics and rendering guidance.

## Cancel, end, and resume

Pass `prewarm: true` to create the session on mount and after `newSession()`. Omit it to create the session on the first send. The composable keeps the session stream open across turns. See [Prewarming](./use-eve-agent#prewarming) for creation and failure behavior, and [Stream lifetime](./use-eve-agent#stream-lifetime) for connection behavior.

Call `cancel()` to stop the turn on the server; the composable stays attached until the turn ends. Offer it while `activeTurn(view.value)` from `eve/events` returns a turn, because `status` reports outstanding work and is `"idle"` while a turn waits only on a person. Disposing the component only disconnects its local stream, and the turn keeps running on the server.

Call `newSession()` to clear local state and start a new session; `end()` instead ends the session on the server.

Pass `initialSession`, `initialEvents`, and `resume: true` to restore a saved conversation and follow a turn that is still running. During catch-up, `status.value` is `"resuming"`. Keep the restored conversation visible, and disable submission until it changes to `"idle"` or `"busy"`. Failures appear in the separate `error` field. Call `resume()` directly to control restoration imperatively. See [Resume a saved session](./use-eve-agent#resume-a-saved-session) for the persistence contract and [Cancelling](./use-eve-agent#cancelling) for cancellation behavior.

## Custom host and credentials

Pass `baseUrl`, `auth`, or `headers` to the composable, as with the other frontend bindings. See [Custom hosts and headers](./overview#custom-hosts-and-headers).

## Attach page context per turn

Pass `clientContext` to `send()` or `respond()`, or use `prepareSend` to add context before every turn. See [Attach page context per turn](./overview#attach-page-context-per-turn).

## Lifecycle callbacks

Pass `onEvent`, `onError`, `onFinish`, or `onSessionChange` to react to events, errors, finished turns, and session changes. See [Lifecycle callbacks](./use-eve-agent#lifecycle-callbacks) for when each one fires and how optimistic messages behave.

## Derive your own state

Use `view` and selectors from `eve/events` for session state, and `messages` for rendering. See [Derive your own state](./overview#derive-your-own-state).
