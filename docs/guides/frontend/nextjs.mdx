Your Next.js app and your eve agent run side by side on the same domain. Pages go to Next.js, and requests to `/eve/v1/*` go to the agent. The agent runs as its own service, never inside the Next.js server.

How you set this up depends on what your project is:

- **An eve project with a web frontend.** The project is built around your agent, and the chat app is one part of it. `eve add channel/web` generates the app for you. See [Add a web frontend to an eve project](#add-a-web-frontend-to-an-eve-project).
- **A Next.js app with an eve agent.** The project is built around your web app, and the agent is one part of it. Wrap `next.config.ts` with `withEve`. See [Add an eve agent to a Next.js app](#add-an-eve-agent-to-a-nextjs-app).

Your React code is the same either way.

## Add a web frontend to an eve project

From your agent project, run the Web Chat installer:

```bash
eve add channel/web
```

It asks two questions:

1. **Framework:** choose **Next.js**.
2. **Authentication:** choose **Sign in with Vercel**, or set it up yourself. See [Authenticate users](#authenticate-users).

In a project with several agents, add `--agent <name>` to pick the one the chat talks to.

The installer creates a Next.js app in `apps/web/`, plus a root `vercel.ts` that deploys the app and the agent together as Vercel services:

```text
project/
├── agent/
│   └── channels/eve.ts       # who can call the agent from a browser
├── apps/web/
│   ├── app/
│   │   ├── _components/      # the chat UI
│   │   ├── page.tsx          # landing page
│   │   └── s/                # conversation pages
│   └── next.config.ts
├── package.json              # dependencies and scripts
└── vercel.ts                 # the app and agent as Vercel services
```

Start it with the command the installer prints:

| Command           | Starts                                  |
| ----------------- | --------------------------------------- |
| `npm run dev:all` | The app and the agent together          |
| `npm run dev:web` | The app alone                           |
| `npm run dev`     | The agent alone, in the eve terminal UI |

`dev:all` needs Vercel CLI 59.16.0 or newer, but not a linked project.

Before you deploy, replace the placeholder auth the installer generates. Until then, production browser requests get `401`. See [Authenticate users](#authenticate-users). To run the app somewhere other than Vercel, see [Run the generated app outside Vercel](#run-the-generated-app-outside-vercel).

### Wire up a frontend by hand

To add a Next.js app you wrote yourself to an eve project, do what the installer does: leave `next.config.ts` alone, and add a `vercel.ts` at the project root that tells Vercel where the app lives:

```ts title="vercel.ts"
import { withEve } from "eve/vercel";

export default await withEve({
  services: {
    web: {
      framework: "nextjs",
      root: "apps/web",
      buildCommand: "node ../../node_modules/next/dist/bin/next build",
    },
  },
  routes: [{ src: "^(.*)$", destination: { type: "service", service: "web" } }],
});
```

`withEve` adds your agents and their routes for you: `/eve/v1/*` for one agent, or `/eve/<name>/v1/*` for each agent in a workspace.

- Install `eve` in the root `package.json`.
- Remove any `vercel.json`.

See [Compose agents with other Vercel services](../deployment/vercel#compose-agents-with-other-vercel-services) for more options.

## Add an eve agent to a Next.js app

When your project is a Next.js app, embed the agent with `withEve` from `eve/next`. Next.js starts the agent next to your app and forwards `/eve/v1/*` to it, so `next dev` and `next start` run both, wherever your app runs today.

Install `eve` in your app (`npm install eve@latest`), then wrap your Next.js config:

```ts title="next.config.ts"
import type { NextConfig } from "next";
import { withEve } from "eve/next";

const nextConfig: NextConfig = {};

export default withEve(nextConfig);
```

`withEve` looks for your agent next to `next.config.ts`. If the agent lives somewhere else, point to it:

```ts title="apps/web/next.config.ts"
export default withEve(nextConfig, { eveRoot: "../.." });
```

This setup needs Next.js 16 and React 19. If you don't have an agent yet, start from [Getting Started](../../getting-started). See [`withEve` options](#witheve-options) for the rest, and [Run, build, and deploy](#run-build-and-deploy) for the commands.

## Build the chat UI

Call `useEveAgent` from a Client Component:

```tsx title="apps/web/app/_components/chat.tsx"
"use client";

import { useEveAgent } from "eve/react";

export function Chat() {
  const agent = useEveAgent();
  const isResuming = agent.status === "resuming";

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        const message = String(new FormData(event.currentTarget).get("message") ?? "").trim();
        if (message.length > 0 && !isResuming) {
          void agent.send(message);
        }
      }}
    >
      {agent.messages.map((message) => (
        <article key={message.id}>
          <header>{message.role}</header>
          {message.parts.map((part, index) =>
            part.type === "text" ? <p key={part.id ?? index}>{part.text}</p> : null,
          )}
        </article>
      ))}
      <input disabled={isResuming} name="message" />
      <button disabled={isResuming} type="submit">
        Send
      </button>
    </form>
  );
}
```

A real chat also needs to show tool calls, approvals, questions, and sign-ins. Without them, a turn that waits on the user can't continue. The generated chat handles all of these. To build your own, see [Human-in-the-loop prompts](/docs/guides/frontend#human-in-the-loop-prompts) and [Sign-ins](/docs/guides/frontend#sign-ins-and-other-interactions).

## Give each conversation a URL

The generated chat gives every conversation its own address:

| URL              | Shows                                                       |
| ---------------- | ----------------------------------------------------------- |
| `/`              | The landing page                                            |
| `/s`             | A new, empty conversation                                   |
| `/s/[sessionId]` | A saved conversation, including any reply still in progress |

The conversation page passes its session ID to the hook:

```tsx title="apps/web/app/s/[sessionId]/page.tsx"
import { SessionChat } from "@/app/_components/session-chat";

export default async function SessionPage({
  params,
}: {
  readonly params: Promise<{ readonly sessionId: string }>;
}) {
  const { sessionId } = await params;
  return <SessionChat key={sessionId} sessionId={sessionId} />;
}
```

```tsx title="apps/web/app/_components/session-chat.tsx"
"use client";

import { useEveAgent } from "eve/react";

export function SessionChat({ sessionId }: { readonly sessionId: string }) {
  const agent = useEveAgent({
    initialSession: { sessionId, streamIndex: 0 },
    resume: true,
  });
  // Render agent.messages as in the basic chat.
}
```

Three things to get right:

- **Change the URL without the router.** Once `/s` creates a session, switch the address to `/s/{sessionId}` with the browser's own `replaceState`. Next.js patches `window.history`, and going through its router would remount the page and cut off the reply:

  ```ts
  History.prototype.replaceState.call(
    window.history,
    window.history.state,
    "",
    `/s/${encodeURIComponent(sessionId)}`,
  );
  ```

- **Use a `key` to switch conversations.** Keying the chat on the session ID gives each conversation a fresh hook.
- **Disable input while loading.** While `status` is `"resuming"`, show the messages but don't accept new ones.

## Authenticate users

The browser calls the agent on your own domain, so it sends your app's cookies along. The agent checks them in `agent/channels/eve.ts`.

Replace the generated `placeholderAuth()` with a function that reads your app's session:

```ts title="agent/channels/eve.ts"
import { type AuthFn, localDev, vercelOidc } from "eve/channels/auth";
import { eveChannel } from "eve/channels/eve";
import { getSession } from "@/lib/auth";

const appSession: AuthFn<Request> = async (request) => {
  const session = await getSession(request);
  if (!session) return null;
  return {
    authenticator: "app",
    principalId: session.userId,
    principalType: "user",
    attributes: {},
  };
};

export default eveChannel({
  auth: [appSession, vercelOidc(), localDev()],
});
```

eve tries each entry in order:

- `appSession` accepts your signed-in users.
- `vercelOidc()` accepts your own server code and the eve terminal UI.
- `localDev()` accepts requests during local development only.

For a public demo, `none()` from `eve/channels/auth` lets anyone in. Don't use it for private data. See [Authentication](../auth-and-route-protection) for more.

If your app uses tokens instead of cookies, pass them to the hook:

```tsx
const agent = useEveAgent({
  auth: { bearer: async () => await getAccessToken() },
});
```

### Sign in with Vercel

Choose **Sign in with Vercel** in the installer to let members of your Vercel team sign in, with nothing to build. It needs a linked Vercel project. Local development skips sign-in. See [Web Chat with Sign in with Vercel](../../channels/eve#web-chat-with-sign-in-with-vercel) for details.

## Save conversations

eve already keeps every conversation, so a URL with a session ID is enough to reopen one. Add your own database when you want a chat list, titles, or faster page loads.

Keep your chat record separate from the eve session. Your record holds the title and owner; eve holds the messages. Store the session and its events alongside your record:

```ts
type SavedChat = {
  id: string;
  ownerId: string;
  session: ClientSessionState | null; // from onSessionChange
  events: SessionStreamEvent[]; // from onEvent
};
```

Then:

1. **Create the chat record before the first message.** If the user reloads mid-reply, the page can still find the conversation.
2. **Save as things happen.** Save `session` in `onSessionChange` and each event in `onEvent`. Don't wait for the reply to finish: a turn waiting on the user hasn't finished.
3. **Load on the server.** Read the saved chat in a Server Component, and pass `events` and `session` to the Client Component as `initialEvents` and `initialSession`, with `resume: true`. Saved messages show at once, and the live reply picks up from there.
4. **Store `session` as eve gives it to you.** Don't compute the cursor from the number of events.

See [Resume a saved session](./use-eve-agent#resume-a-saved-session) for how saved events and catch-up fit together.

## Call the agent from server code

Route Handlers, Server Actions, and cron jobs can call the agent with `Client` from `eve/client`. Point it at your own domain, and sign requests with your project's Vercel OIDC token:

```ts title="apps/web/app/api/summarize/route.ts"
import { getVercelOidcToken } from "@vercel/oidc";
import { Client } from "eve/client";
import { getSession } from "@/lib/auth";

export async function POST(request: Request) {
  const session = await getSession(request);
  if (!session) return new Response("Unauthorized", { status: 401 });

  const client = new Client({
    baseUrl: new URL(request.url).origin,
    auth: { vercelOidc: { token: async () => await getVercelOidcToken() } },
    redirect: "manual",
  });

  const { delivery } = await client.sessions.create({ message: "Summarize today's tickets." });
  const result = await delivery.result();
  return Response.json({ status: result.status });
}
```

- Check who's calling before you call the agent, as above. The OIDC token gives your code the app's own access, so an unchecked route would let anyone use it.
- Install `@vercel/oidc`, and run `eve link` once so the token works locally.
- The token identifies your app, not a user. To act as the signed-in user, forward their cookie in `headers` instead.
- Without an incoming request, as in a cron job, use `https://${process.env.VERCEL_URL}` as the domain.

See [Client SDK](/docs/guides/client) for more.

## Use multiple agents

With several agents, each one gets its own path, such as `/eve/support/v1/*`. Pick one in the hook:

```tsx
const support = useEveAgent({ agent: "support" });
```

- Give each chat page one agent, and include the agent name in its URLs.
- Remount the chat when switching agents.
- Set up authentication for each agent.

Both `eve/next` and `eve/vercel` find the agents in your project automatically. With `eve/next`, you can also list agents that live elsewhere:

```ts title="next.config.ts"
export default withEve(nextConfig, {
  agents: {
    support: "./apps/support-agent",
    billing: { root: "./apps/billing-agent", buildCommand: "pnpm build:billing-agent" },
  },
});
```

Use either `eveRoot` or `agents`, not both.

## Run, build, and deploy

### Run locally

- **eve project with a web frontend:** `npm run dev:all`.
- **Next.js app with `eve/next`:** `next dev`, or `npm run dev:web` for an app in `apps/web/`. Next.js starts the agent for you. To use an agent you already started, set `EVE_BASE_URL` to its address.

### Deploy to Vercel

From the project root:

```bash
eve link
eve deploy
```

The app and each agent deploy together as one Vercel project. With `eve/next` and an `agents/` workspace, `next build` also writes `.eve/agent-summary.json` in the `eveRoot` directory, which Vercel uses to show each agent's tools, schedules, and connections on the project overview. See [Deploy to Vercel](../deployment/vercel) for credentials and sandboxes.

<Callout type="warning" title="eve/next in apps/web">
  When an app in `apps/web/` embeds the agent with `eve/next`, Vercel doesn't build it by default.
  In your Vercel project settings, set the Build Command to `npm run build:web` and the Output
  Directory to `apps/web/.next`.
</Callout>

### Run a production build

With `eve/next`, `next start` runs the built agent too, on any Node host. Build both first:

```bash
eve build
npm run build:web
npx next start apps/web
```

The agent listens on port `4274`. Set `EVE_NEXT_PRODUCTION_PORT` to change it. With several agents, a root `eve build` doesn't build them for `next start`. Run `eve build` in each `agents/<name>/` directory instead.

To run the agent in its own process instead, put it behind a proxy that serves it under the private path `/_eve_internal/eve` (the `servicePrefix` option). Then set `EVE_NEXT_PRODUCTION_ORIGIN` to that proxy's address when you build and start Next.js.

For authentication, the Workflow world, and sandboxes outside Vercel, see [Self-host eve](../deployment/self-hosting).

### Run the generated app outside Vercel

The generated app runs its agent as a Vercel service through `vercel.ts`, which only Vercel reads. To run it anywhere else, embed the agent in the app with `eve/next`, as in [Add an eve agent to a Next.js app](#add-an-eve-agent-to-a-nextjs-app):

1. Replace `apps/web/next.config.ts` with:

   ```ts title="apps/web/next.config.ts"
   import type { NextConfig } from "next";
   import { withEve } from "eve/next";
   import { fileURLToPath } from "node:url";

   const nextConfig: NextConfig = {};
   const eveRoot = fileURLToPath(new URL("../..", import.meta.url));

   export default withEve(nextConfig, { eveRoot });
   ```

2. Delete the root `vercel.ts`, and the `dev:eve` and `dev:all` scripts from `package.json`.
3. Run it with `npm run dev:web`, and build and start it as in [Run a production build](#run-a-production-build).

When `next.config.ts` matches the file above, rerunning `eve add channel/web` keeps this setup.

To keep the app and the agent as separate processes instead, run them behind your own reverse proxy. See [Run workspace members](../deployment/self-hosted-operations#run-workspace-members) and [Add a peer frontend](../deployment/self-hosted-operations#add-a-peer-frontend).

## Troubleshooting

| You see                                                        | Fix                                                                                                                        |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `401` "Production auth is not configured"                      | Replace `placeholderAuth()`. See [Authenticate users](#authenticate-users)                                                 |
| "The Next.js output directory `.next` was not found" on deploy | Set the Build Command and Output Directory. See [Deploy to Vercel](#deploy-to-vercel)                                      |
| The reply stops after the first message                        | Change the URL with `History.prototype.replaceState`. See [Give each conversation a URL](#give-each-conversation-a-url)    |
| Messages repeat or vanish after a reload                       | Save `session` from `onSessionChange` as is                                                                                |
| `next dev` times out waiting for the agent                     | Raise `devServerTimeoutMs`                                                                                                 |
| A custom channel route returns `404` with Vercel services      | Route it to the agent in `vercel.ts`. See [Compose agents](../deployment/vercel#compose-agents-with-other-vercel-services) |

## Reference

### `withEve` options

Options for `withEve` from `eve/next`. All are optional.

| Option               | Default                  | Purpose                                                                                            |
| -------------------- | ------------------------ | -------------------------------------------------------------------------------------------------- |
| `eveRoot`            | The Next.js app root     | Where your agent project lives                                                                     |
| `agents`             | Found automatically      | Agents to mount at `/eve/<name>/v1/*`. Each is a path or `{ root, buildCommand?, servicePrefix? }` |
| `eveBuildCommand`    | Runs the installed `eve` | Command that builds each agent                                                                     |
| `devServerTimeoutMs` | `180000`                 | How long `next dev` waits for each agent to start                                                  |
| `servicePrefix`      | `"/_eve_internal/eve"`   | Private route path for self-hosted proxying and hand-written Vercel services                       |

### Environment variables

| Variable                     | Purpose                                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| `EVE_BASE_URL`               | `eve/next`, development: use an agent you already started                                             |
| `EVE_NEXT_PRODUCTION_PORT`   | `eve/next`: first port for agents that `next start` runs. Defaults to `4274`                          |
| `EVE_NEXT_PRODUCTION_ORIGIN` | `eve/next`: address of a proxy serving your agents under `servicePrefix`. Turns off automatic startup |
| `EVE_PUBLIC_ROUTE_PREFIX`    | Self-hosting: an agent's public path, such as `/eve/support`, so callback links work                  |
