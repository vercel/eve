A Teams agent answers personal chats, and messages that mention it in group chats and channels. Replies post as Markdown in the conversation, and approvals and questions appear as Adaptive Cards. [Set up](#set-up) creates and installs the Teams app through Vercel Connect.

For information on all configuration and customization options, see the [Teams reference](/docs/channels/teams/reference).

eve add channel/teams

Setup runs the Vercel Connect CLI, which creates and installs a managed Microsoft Teams app, including administrator consent, routes verified activities to `/eve/v1/teams`, and writes the channel file:

```ts title="agent/channels/teams.ts"
import { connectTeamsCredentials } from "@vercel/connect/eve";
import { teamsChannel } from "eve/channels/teams";

export default teamsChannel({
  credentials: connectTeamsCredentials("microsoft-teams/my-agent"),
});
```

After deploying, mention the bot in a channel or send it a personal message.

## Default channel behavior

By default, the bot answers personal chats, and messages that mention it in group chats and channels. Each channel or group-chat thread is its own session, and replies post as Markdown in the conversation.

- To customize which messages start a turn, override `onMessage`. See [Dispatch](/docs/channels/teams/reference#dispatch).
- To answer thread replies without a mention, see [Reply without a mention](#reply-without-a-mention).
- To change how replies are sent, see [Delivery](/docs/channels/teams/reference#delivery).

## Reply without a mention

Group chats and channels need a mention on every message. This `onMessage` also answers any conversation the agent is already part of:

```ts title="agent/channels/teams.ts"
import { defaultTeamsAuth, teamsChannel } from "eve/channels/teams";

export default teamsChannel({
  async onMessage(ctx, message) {
    if (message.from.role === "bot" || message.from.id === message.recipient.id) return null;
    const isDirectMessage = message.scope === "personal";
    return isDirectMessage || message.isBotMentioned || (await ctx.isSubscribed())
      ? { auth: defaultTeamsAuth(message) }
      : null;
  },
  // A custom onMessage turns off the default card-submission auth.
  onAnswers: (_ctx, activity) => ({ auth: defaultTeamsAuth(activity) }),
});
```

A custom `onMessage` makes eve reject approval and question card submissions until you also set `onAnswers`, so a card can't bypass your message check. If `onMessage` restricts who can reach the agent, apply the same rule in `onAnswers`.

## Configure approval prompts

Tool approvals and questions render as Adaptive Cards with buttons, selects, or a text input. When an approval settles, eve replaces the card with the outcome and who answered.

When a tool needs a connection the person hasn't authorized, a personal chat shows the sign-in link directly. In group chats and channels, the shared card has a **Sign in** button, and only the person who needs to sign in can open the link.

## Handle file attachments

Images pasted into a message and files uploaded in a personal chat reach the agent as files. Personal-chat uploads need `supportsFiles: true` on the bot in your Teams app manifest. See [Attachments](/docs/channels/teams/reference#attachments) for limits and other file hosts.
