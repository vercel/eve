This page documents every part of `teamsChannel` from `eve/channels/teams`. For setup and common tasks, start with [Microsoft Teams](/docs/channels/teams).

The Teams channel runs your agent as a Microsoft Teams bot. It lives in `agent/channels/teams.ts`. It checks each incoming Bot Framework Activity's Bot Connector bearer JWT and `serviceurl` claim. It replies through the Bot Framework Connector REST API. Approvals and questions render as Adaptive Cards.

## Add the channel

```ts title="agent/channels/teams.ts"
import { teamsChannel } from "eve/channels/teams";

export default teamsChannel();
```

### Vercel Connect

For a managed Teams bot on Vercel, run:

```bash
eve add channel/teams
```

The guided flow runs the Vercel Connect CLI to create and install a managed Microsoft Teams app, and routes verified Activities to `/eve/v1/teams`. It writes:

```ts title="agent/channels/teams.ts"
import { connectTeamsCredentials } from "@vercel/connect/eve";
import { teamsChannel } from "eve/channels/teams";

export default teamsChannel({
  credentials: connectTeamsCredentials("microsoft-teams/my-agent"),
});
```

Vercel Connect handles Microsoft administrator consent and app installation. After you deploy, mention the bot in a channel or send it a personal message.

### Portable credentials

To manage the bot registration and credentials yourself, set:

```bash
MICROSOFT_APP_ID=...
MICROSOFT_APP_PASSWORD=...
MICROSOFT_TENANT_ID=...   # optional, single-tenant bots
```

The channel mounts at `POST /eve/v1/teams`. Pass `route`, such as `route: "/api/teams/activity"`, to mount it elsewhere. Point your Azure Bot or Teams app messaging endpoint at that public URL.

## Dispatch

By default, the bot answers personal-chat messages, and channel or group-chat messages that mention it. It ignores messages that reach it through resource-specific consent without a mention. Each channel or group-chat thread gets its own session, keyed by its root activity id.

eve strips the bot mention from the text. The model sees a `<teams_context>` block with `user_id`, `bot_id`, and `is_mentioned`.

A custom `onMessage` returns `{ auth }` to run the agent, optionally with `title` to set the run title, or `null` to ignore the message. To continue active threads without another mention, use `ctx.isSubscribed()`. It reports whether a session already answers in the thread:

```ts
import { defaultTeamsAuth, teamsChannel } from "eve/channels/teams";

export default teamsChannel({
  async onMessage(ctx, message) {
    // Never answer bots, including this one.
    if (message.from.role === "bot" || message.from.id === message.recipient.id) return null;
    const isDirectMessage = message.scope === "personal";
    return isDirectMessage || message.isBotMentioned || (await ctx.isSubscribed())
      ? { auth: defaultTeamsAuth(message) }
      : null;
  },
  // A custom onMessage turns off the default card-submission auth.
  onAnswers: (_ctx, activity) => ({ auth: defaultTeamsAuth(activity) }),
});
```

## Restrict who can reach the agent

A valid Bot Connector token proves that Teams sent the activity, not that the sender should reach your agent. Shared channels can include people from other Microsoft Entra tenants, and anything the agent posts there is visible to them. Guests are in your tenant but outside your organization, and anonymous participants join meetings without an account.

`admit(request)` is the channel's single access check. eve calls it before any hook, and before `receive` starts a session in a conversation:

| `request.kind` | Surface                                                           | When `admit` returns `false` or throws                                                |
| -------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `message`      | Messages, before `onMessage`                                      | Dropped                                                                               |
| `answer`       | Approval and question card submissions, and **Sign in** presses   | Rejected; the request and its card stay open. A sign-in press is told it isn't theirs |
| `invoke`       | `onInvoke` activities                                             | Acknowledged with `200 OK`; the hook doesn't run                                      |
| `send`         | `receive`, through `to(teams, target)` or `ctx.to(teams, target)` | Throws before anything is posted                                                      |

The default, `defaultTeamsAdmit`, refuses:

- conversations that name no tenant, or conflicting ones in `channelData.tenant.id` and `conversation.tenantId`.
- conversations in a tenant other than `credentials.tenantId` (or `MICROSOFT_TENANT_ID`), when one is set. A multi-tenant bot without it admits whichever tenant installed it.
- channels Teams marks as shared (`channelData.channel.type: "shared"`).
- people whose conversation membership reports another tenant.
- guests and anonymous participants (`userRole` of `guest` or `anonymous`).
- people Teams can't look up, or whose membership doesn't report a tenant.

For each request with a sender, eve looks the person up with the Bot Connector's `GET /v3/conversations/{id}/members/{userId}`. A channel's roster lives on its team, so eve asks the team. It caches the answer for five minutes, or one minute after a failed lookup. A send has no sender, so it checks only `target.tenantId`, which the default requires. eve can't tell from a send target whether a channel is shared.

The request carries:

- `kind`, from the table above
- `conversationId`, the conversation the request comes from or a send posts into, without a thread suffix
- `conversationType`, such as `personal`, `groupChat`, or `channel`
- `tenantId`, the conversation's tenant
- `actor`, the sender's Bot Framework `userId` and, when Teams reports it, their Microsoft Entra `aadObjectId`. It's `undefined` for sends.
- `isExternalConversation()`, the tenant and shared-channel checks the default makes. It returns `true` when Teams can't classify the conversation or the sender.
- `isGuest()`, the guest and anonymous check the default makes. It returns `true` when Teams can't look the sender up, and `false` without an actor.
- `raw`, the verified activity, or the receive target for a send
- `teams`, the Bot Connector handle for the conversation

Write your own `admit` to change the policy. Call `defaultTeamsAdmit` from it to keep the tenant and guest checks. This one adds an allowlist of Microsoft Entra object ids:

```ts title="agent/channels/teams.ts"
import { defaultTeamsAdmit, teamsChannel } from "eve/channels/teams";

const allowedUsers = new Set(["00000000-0000-0000-0000-000000000001"]);

export default teamsChannel({
  async admit(request) {
    if (!(await defaultTeamsAdmit(request))) return false;
    return request.kind === "send" || allowedUsers.has(request.actor?.aadObjectId ?? "");
  },
});
```

To serve a partner in one conversation, admit it before the default. To let guests in but keep the tenant checks, skip `isGuest()`:

```ts
admit: async (request) =>
  request.conversationId === "19:partner@thread.tacv2" || (await defaultTeamsAdmit(request)),

admit: async (request) => !(await request.isExternalConversation()),
```

Pass `admit: () => true` to admit every request.

- `onMessage` and `onAnswers` still decide routing and auth. A hook that returns `null` drops a request `admit` let through.
- The default looks up every sender, other bots included. If Teams can't look a bot up, the default refuses its messages.
- Keep authorization checks in sensitive tools too. `admit` controls who reaches the agent; tool checks control what that person may read or change.

## Delivery

Replies post as Markdown (`textFormat: "markdown"`), and long text is split across messages. A typing indicator shows when a turn starts and on each tool call. `thread.mentionUser()` shows the display name, or the user ID, as literal text, while the mention still targets the original user.

Each activity's `serviceUrl` must match the `serviceurl` claim in its verified token. A custom `webhookVerifier` replaces this check, so it must authenticate both the activity and its service URL. Load proactive conversation references from your own verified records, never from a URL a caller supplies.

Outbound Connector requests need an HTTPS URL without credentials, a query string, or a fragment, and don't follow redirects. Bot Framework Emulator's HTTP service URLs don't work, even with a custom verifier. Use an HTTPS endpoint or proxy to test the Connector locally.

## Human-in-the-loop (HITL)

Each approval or question (`interaction.opened`) renders as an Adaptive Card. Approval cards show the tool input in the card and in the fallback text. Buttons and options map to `Action.Submit`, selects to `Input.ChoiceSet`, and free text to `Input.Text`. A select's `initialOptionId` becomes the choice set's starting value, so **Submit** sends that option unless the person changes it. Submissions don't need a mention, and each one resumes the thread recorded in its card.

By default, a submission answers as the Teams user who clicked. If you set `onMessage`, also set `onAnswers` with the same policy. Otherwise eve rejects every card submission. Return `{ auth: defaultTeamsAuth(activity) }` to accept the submitting user.

When a tool approval is decided, eve replaces its card with the outcome and the responder's name. A response the approval policy rejects leaves the card unchanged. A submission to a card whose session has ended replaces the card with its prompt and `No longer active`. eve then tells the submitter to send a new message.

## Connection sign-ins

When a connection needs the person to sign in, eve posts an Adaptive Card:

- **In a personal chat**, the card has the sign-in link and any confirmation code.
- **In group chats and channels**, the shared card says who has to sign in and has a **Sign in** button (`Action.Execute`). eve identifies whoever presses it through `onAnswers`. The requester gets a card with the link and code that only they can see. Anyone else is told they can't open it, so no other member can save their account under the requester's identity.

If you customize `onMessage` without setting `onAnswers`, eve rejects every press, so nobody can open a sign-in from a group chat or channel.

## Proactive sessions

Proactive sessions need an existing conversation reference, because the Bot Framework v1 API can't create chats by Azure Active Directory (AAD) user id. Pass `serviceUrl`, `conversationId`, `tenantId`, and the other reference fields as the target. The default `admit` refuses a target without `tenantId`. Call `to(teams, target).send(message, { auth })` from a schedule `run` handler, or `ctx.to(teams, target).send(message, { auth })` from another channel.

## Attachments

Inbound files reach the agent as files:

- eve downloads pasted images from Microsoft Bot Connector hosts with your bot credentials.
- eve downloads personal-chat uploads from their pre-authenticated SharePoint URL (`*.sharepoint.com` or `*.sharepoint.us`). They need `supportsFiles: true` on the bot in your Teams app manifest.
- A failed download, or a file over the upload limit (25 MB unless `files.uploadPolicy` sets `maxBytes`), reaches the agent as a short note.

Use `allowedHosts` to download from other hosts without credentials, or `enabled: false` to drop attachments:

```ts
export default teamsChannel({
  files: { allowedHosts: ["files.contoso.com"] },
});
```

## Options

`teamsChannel(config)` takes these options. All are optional.

| Option                | Default                                                                 | Description                                                                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `credentials`         | `MICROSOFT_APP_ID`, `MICROSOFT_APP_PASSWORD`, and `MICROSOFT_TENANT_ID` | From `connectTeamsCredentials(...)`, or `{ appId, appPassword, tenantId, tokenProvider, webhookVerifier }`. `TEAMS_APP_ID`, `TEAMS_APP_PASSWORD`, and `TEAMS_TENANT_ID` also work. |
| `route`               | `/eve/v1/teams`                                                         | Messaging endpoint path.                                                                                                                                                           |
| `api`                 | `https://login.microsoftonline.com` and the global `fetch`              | `{ loginBaseUrl, fetch }` for Connector token requests.                                                                                                                            |
| `adaptiveCardVersion` | `"1.5"`                                                                 | Adaptive Card schema version for HITL and sign-in cards.                                                                                                                           |
| `admit`               | `defaultTeamsAdmit`                                                     | `(request)` check that runs before every hook and proactive send. See [Restrict who can reach the agent](#restrict-who-can-reach-the-agent).                                       |
| `turnPolicy`          | `"steer"`                                                               | `"steer"` or `"queue"` for messages that arrive during a turn.                                                                                                                     |
| `files`               | Enabled, Microsoft hosts only, up to 25 MB                              | `{ enabled, allowedHosts, uploadPolicy }`. See [Attachments](#attachments).                                                                                                        |
| `onMessage`           | Personal chats and direct mentions                                      | `(ctx, message)` hook. Return `{ auth }` to dispatch or `null` to ignore.                                                                                                          |
| `onAnswers`           | The submitting user, unless `onMessage` is set                          | `(ctx, activity)` hook that authorizes HITL submissions. With a custom `onMessage` and no `onAnswers`, eve rejects them.                                                           |
| `onInvoke`            | Acknowledge with `200 OK`                                               | `(ctx, activity)` hook for invokes that aren't HITL.                                                                                                                               |
| `events`              | eve's default handlers                                                  | Per-event handler overrides.                                                                                                                                                       |

The channel mounts `POST /eve/v1/teams`.
