The Teams channel runs your agent inside Microsoft Teams as a bot. It takes Bot Framework Activity POSTs, checks the Bot Connector bearer JWT on each one, and routes message activities to your agent. Human-in-the-loop (HITL) prompts come back as Adaptive Cards, and replies go out over the Bot Framework Connector REST API. See [Channels](./overview) for the contract this builds on.

## Add the channel

```ts title="agent/channels/teams.ts"
import { teamsChannel } from "eve/channels/teams";

export default teamsChannel();
```

```bash
MICROSOFT_APP_ID=...
MICROSOFT_APP_PASSWORD=...
MICROSOFT_TENANT_ID=...   # optional, single-tenant bots
```

By default the channel mounts at `POST /eve/v1/teams`. Point your Azure Bot or Teams app messaging endpoint at that public URL. To mount somewhere else, pass `route: "/api/teams/activity"`.

## How the channel handles messages

### Dispatch

The default `onMessage` handles two cases: personal-chat messages, and channel or group-chat messages that mention the bot directly. Ambient resource-specific-consent messages are dropped unless you override it. Before dispatch, eve strips the mention, adds a `<teams_context>` block, and scopes channel and group threads by the `;messageid=` root in `conversation.id`, then `replyToId`, then the activity id.

```ts
import { teamsChannel } from "eve/channels/teams";

export default teamsChannel({
  onMessage(_ctx, message) {
    if (message.scope !== "personal" && !message.isBotMentioned) return null;
    return {};
  },
});
```

### Delivery

Replies post as Markdown (`textFormat: "markdown"`), with oversized text split across messages and a typing indicator sent on turn start and action requests.

### Human-in-the-loop (HITL)

A human-in-the-loop (HITL) `input.requested` event renders as an Adaptive Card. Tool approvals show the tool arguments in the card and fallback text. Buttons and options map to `Action.Submit`, selects to `Input.ChoiceSet`, and freeform to `Input.Text`. Teams may return a card submission as either a message or an invoke. eve handles both forms before the normal message mention gate and resumes the thread recorded in the card.

By default, messages and card submissions use the submitting Teams user's auth, including `from.aadObjectId` as `subject` when Teams provides it. Use `authorizeActivity` for allowlists and other identity policy. The same policy runs for both paths, and returning `null` rejects the activity.

```ts
import { defaultTeamsAuth, teamsChannel } from "eve/channels/teams";

function isAllowed(aadObjectId: string | undefined) {
  return aadObjectId === process.env.TEAMS_APPROVER_AAD_OBJECT_ID;
}

export default teamsChannel({
  authorizeActivity(_ctx, activity) {
    if (!isAllowed(activity.from.aadObjectId)) return null;
    return { auth: defaultTeamsAuth(activity) };
  },
});
```

`onMessage` now controls mention gating and extra model context, not authentication. If you previously returned `auth` from `onMessage`, move that logic to `authorizeActivity`. To prevent an existing message allowlist from silently leaving approvals open, eve rejects HITL submissions when you customize `onMessage` without also configuring `authorizeActivity`.

HITL cards carry a signed route back to the parked session. eve uses `credentials.appPassword` as the signing secret by default. Set `credentials.hitlSecret` when you use `tokenProvider`, a custom webhook verifier without an app password, or a separate rotated secret. Cards created before this version have no signed route and fail closed with an expiration message. Ask the agent to create a new card.

For invokes that aren't HITL, handle them in `onInvoke(ctx, activity)`.

### Proactive sessions

Proactive sessions need an existing conversation reference, because the Bot Framework v1 surface cannot create new chats by Azure Active Directory (AAD) user id. Pass `serviceUrl`, `conversationId`, and the other reference fields to `receive(teams, { target })`.

### Attachments

Inbound files are off by default. Opt in to allow personal-scope downloads and public media URLs:

```ts
export default teamsChannel({
  files: { enabled: true, allowedHosts: ["contoso.sharepoint.com"] },
});
```
