# Human writing evaluation

Run this checklist internally after editing, detecting, or drafting. Treat every item as pass or fail. Fix failures before responding, and do not print the checklist unless the user asks for it.

## Fidelity and voice

1. Does the result preserve the writer's point, intent, facts, nuance, and necessary uncertainty?
2. Does every claim, example, statistic, date, source, quotation, product detail, opinion, and reaction come from the source or the user's brief?
3. Does the result preserve distinctive vocabulary, cadence, bluntness, humor, fragments, digressions, profanity, and useful rough edges?
4. Would the writer recognize the result as their own voice?
5. Did the edit leave strong human sentences alone and make only proportional changes?

## Clarity and substance

1. Does the piece lead with what its audience needs while retaining setup that adds context, tension, or character?
2. Are tangled sentences fixed without flattening clear spoken cadence?
3. Are concrete, supported details protected rather than replaced with generic claims?
4. Do direct verbs and natural subjects carry the prose where they improve clarity?
5. Does each remaining sentence contribute information, reasoning, voice, or necessary transition?

## Pattern check

1. Are unsupported importance, promotional claims, notability padding, superficial analysis, vague attribution, and formulaic outlooks removed or flagged?
2. Are stock contrasts, throat-clearing, faux insights, colon reveals, rhetorical setups, negative listings, decorative fragments, forced trios, and false ranges fixed when they add no value?
3. Are empty vocabulary clusters, fake-strong verbs, synonym cycling, filler, stacked hedging, and chatbot artifacts removed without banning legitimate language?
4. Are robotic rhythm, fake-profound endings, redundant conclusions, decorative formatting, and punctuation crutches corrected where appropriate?
5. Were intentional constructions and required house-style choices preserved?

## Technical documentation

1. Does the page have a clear audience and goal, use established terminology, and stay focused on one job?
2. Are technical claims and code examples accurate, current, and supported by the code or an authoritative source?
3. Does the page use a neutral instructional voice, descriptive sentence-case headings, and formatting that supports scanning?
4. Are code examples minimal, explained, language-tagged, and consistent with repository conventions?
5. For a review, does each finding include a concise, clickable `file:line` location?

## Response contract

1. For an edit, is the full edited draft present, followed by a short **What changed** section unless the user requested clean copy only?
2. For detection, does each finding name a pattern, quote the affected text, and suggest a brief fix without rewriting, scoring, or claiming AI authorship?
3. For a draft, does the prose follow the requested audience, format, tone, and supplied voice without inventing personal experience?
4. Is the evaluation omitted unless the user requested it?
