Add durable event subscriptions for channels, discovered with `eve__search`, and unify subscription tools across channels and MCP connections.

- Custom channels can define `experimental.subscriptions` on `defineChannel` to let sessions subscribe, with `events` (each with a `name`, `description`, and `inputSchema`) as the required registry of the events the channel emits, `onEvent`, and call `experimental.subscriptions.emit(event, input, { id, data })` from route handlers. `onEvent` returns a message or `null`. `onSubscribe` can deny a subscription by throwing, or narrow its scope. The types are exported from `eve/experimental/channels`.
- The root agent now uses one fixed `eve__subscribe` and `eve__subscription_stop` for both channels and MCP `experimental.events` connections, and finds the events with `eve__search`. `eve__subscribe` takes a flat `{ source, event, input, ttlMs }`, does not list events in its schema, and rejects an unknown event with the closest names. Subagents do not get these tools.
- **Breaking for MCP `experimental.events`.** `eve__subscription_get`, the per-connection `events_get_subscription` and `events_unsubscribe` tools, and the generated `events_subscribe_<hash>` tools are removed. A connection's events appear in `eve__search` results, and eve calls the server's `events/list` only when a search covers the connection or a subscribe runs. `tools.allow` and `tools.block` no longer filter event subscriptions, so use the connection's `approval`. To migrate, call `eve__search` for the event and then `eve__subscribe` with `{ source, event, input, ttlMs }`.
- `githubChannel({ experimental: { subscriptions: { onEvent, events } } })` enables subscriptions to GitHub webhook events per repository or pull request, with `onEvent` filtering and formatting each delivery and the optional `events` narrowing which of GitHub's events `eve__search` offers and `eve__subscribe` accepts. Pass `onComment: () => null` if you also want to disable default `@mention` comment sessions.
