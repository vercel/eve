Add durable channel event subscriptions. Custom channels declare `subscriptions` (`description`, `events`, `inputSchema`, `onEvent`) on `defineChannel` and call `emit(event, input, { id, data })` from routes. `subscribe`, `get_subscription`, and `stop_subscription` validate event names against each source's declared catalog and queue matching occurrences under the subscribing session's saved auth. `githubChannel` exposes GitHub webhook events (such as `check_suite.completed` or `issue_comment.created`) per repository or pull request. The GitHub channel's catalog is GitHub's full list of webhook event names from `@octokit/webhooks` (`check_suite.completed`, `issue_comment.created`, `push`, ...); `subscribe` accepts only those names; `onEvent` is the only filter and decides, per subscription and delivery, whether an event is delivered (return `true` for the default message, a string for your own message, `false` or nothing to drop). Subscriptions deliver only to subscribing sessions and never open a new GitHub session; pass `onComment: () => null` on `githubChannel` if you also want to disable default `@mention` comment sessions.
