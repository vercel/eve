`defineAgent`, `defineRemoteAgent`, and `defineWorkflowTool` accept `timeout`: the time limit for each call, in milliseconds, or `false` for no limit beyond the session's lifetime. A call still working at its limit fails with `TIMED_OUT`, whose message names the limit; time the call spends waiting on a question or approval does not count. Agents default to 2 hours of active time, and a root agent's `timeout` applies to its built-in `agent` copies; workflow tools default to no limit. At the limit, eve first reads a workflow tool's run once, so a run that finished but whose outcome was lost settles the call with that outcome. When a call times out or is cancelled, a local agent that has not stopped within 30 seconds has its session terminated, so its `agentId` can no longer be continued, and a workflow tool run that has not ended within 35 seconds is stopped outright. A retried start of a workflow tool call no longer runs its body twice, and an `input.requested` event for a workflow tool call's question or approval now carries the call's `taskId`.
