Ask the caller to approve a call that needs their identity after someone else spoke in a shared session, and let a tool act for another person with `ctx.getToken(provider, { as })`.

Where the session can ask for input, a call that reads the caller's user-scoped token or calls a `forwardPrincipal` connection after someone else spoke stops and opens an ordinary approval for the caller, with `audience.principalIds` naming them, instead of failing. The prompt names the call by its tool, never by text the model wrote, then quotes the latest message from someone else in the turn, escaped, and lists each top-level input field last; in a local subagent the quote can come from the turn that delegated to it. A long value is cut on its own, with a note of how much is hidden. Slack shows the whole prompt beside the approval card. Only the caller can approve it, whatever the tool's `response` policy, and anyone signed in can cancel it, which fails the call. Approving runs the tool again from its first line with the caller's identity, so work it did before asking for the token runs again. On the stream, the call's `call.started` comes before the approval and again when it runs. The approval covers only its own call and doesn't change `ctx.session.auth.sender`. A message that joins the turn leaves the request open, and the call waits as a task. `openCodeChannel()` asks the same way, since it opens a session as the caller, and returns `unavailable` only where eve can't ask.

`defineAgent({ callerConfirmation })` decides when eve asks: `"always"` (the default) before each such call until the caller speaks again, `"once"` once for each signed-in person who spoke after the caller, for the session, and `"never"` not at all. Under `"once"`, the prompt says, before the quote, that approving lets that person steer calls that use the caller's identity for the rest of the conversation. Remote agents that forward the caller follow it too, and a local subagent keeps the `"once"` approvals given in the session that delegated to it. Workflow tools, which can't ask, honor `"never"` but not a `"once"` approval. It governs the caller's identity only: `ctx.session.auth.sender` still names who spoke last, and eve's own role checks still ask about both people. Set it on the root agent; a local subagent that sets it fails to compile, and a dynamic subagent that sets it fails when selected.

`ctx.getToken(provider, { as })` and `ctx.requireAuth(provider, { as })` read the token of another person who has spoken in the session, named by `principalId`; in a local subagent, `as` can also name anyone who had spoken in the session that delegated to it. eve hands the token out when that person sent the latest message or approves the call, and otherwise asks them, signing them in if they haven't connected. For someone other than the caller, the result's `principal` is who eve resolved. A name that matches no one fails with `reason: "principal_not_found"`, and one that matches two people signed in different ways fails with `reason: "principal_ambiguous"`. eve keeps a person's identity but not their attributes, so a provider that reads `principal.attributes` receives none for them. With user tokens, the git extension's `gh` tool takes an `actor` input, passes it as `as`, and asks `authorize` about the person eve resolved.
