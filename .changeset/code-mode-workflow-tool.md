Replace the experimental `Workflow` tool and the `eve/tools/workflow` helper with `experimental.codeMode: true`. The framework `code_mode` tool runs a model-written JavaScript program as a durable workflow: built-in tools, authored tools, and subagents stay directly callable and can also be called from the program, while eligible dynamic tools (including discovered connection tools) are called through the program with on-demand discovery via `tools.search_tools` and `tools.describe_tools`. Each nested call runs as its own step that resumes after authorization, context updates flow back to the parent session (`CODE_MODE_STATE_CONFLICT` on concurrent writes to one field), and each program may invoke at most `experimental.codeMode.maxSubagents` subagents (default 100). Authored workflow tools (`defineWorkflowTool`) stay directly callable and can also be awaited from a program, where their body runs inside the program's workflow run. Approval-gated tools can be called from a program too: the approval renders on the session channel as a tool-approval request for the nested tool, `once()` approvals carry over to later calls and to the parent session, and a denial rejects the call with `CODE_MODE_APPROVAL_DENIED` (approval-gated dynamic tools become program-only). Ordinary background tools and framework controls stay direct only; program errors return to the model without retrying the unchanged source. Programs can call `ask_question` and await the person's answer before continuing. Development workflow steps retain their delivery's compiled agent snapshot across authorization contexts, preventing code-mode calls from failing with a missing generation binding. Approval-state helpers remain separate from Node-only request handlers so code-mode workflow bundles build successfully.
