Let anyone in a shared session steer the running turn without blocking it, and ask a person before a call uses their identity after someone else has spoken.

**Steering.** A message from another person joins the running turn instead of waiting for it to end. The turn keeps its caller, `ctx.session.auth.sender` names who sent the latest message the turn read, and eve tells the model who sent a message when the speaker changes. Only the session-limit prompt keeps other people's messages waiting for a turn of their own. Set `turnPolicy: "queue"` to keep a message waiting for the turn to end. eve saves a turn, or the history before a compaction, to memory only when the slot's scope belongs to everyone who spoke in it, so `byPrincipal` skips a turn someone else spoke in and a shared scope keeps it. Sessions with one person don't change.

**Open waits.** A message that joins a turn waiting on an approval or sign-in no longer withdraws it, even with `turnPolicy: "queue"`. Each call that still waits returns a receipt and becomes a task: the model reads the step's other results, the message, and a `[Tasks]` note that lists the call as `awaiting-approval` or `awaiting-sign-in`. When the person approves or completes the sign-in, the call runs and its result reaches the model in a `task.result` message; a denial arrives the same way. The model can drop a waiting call with `eve__task_cancel`, and from the first waiting call on the session offers `eve__task_wait` and `eve__task_cancel`. The turn doesn't end while such a call waits; cancelling the turn, clearing the session, or a failed turn stops it, and it never reports. A waiting call keeps the `auth.sender` it was asked under. On the stream the request stays `open` and its card keeps working; these calls publish no `task.*` events, and `turn.paused` names the open requests whenever the turn stops to wait. Clients that cleared a card when the next message arrived should keep it until `interaction.settled`.

**The caller's identity.** After someone other than the caller speaks, a call that reads the caller's user-scoped token, calls a `forwardPrincipal` connection, or calls a remote agent that forwards the caller needs the caller. Where the session can ask, the call stops and opens an approval that only the caller can approve; anyone signed in can cancel it, which fails the call. The prompt names the tool, never text the model wrote, quotes the latest message from someone else, escaped, and lists each input field, cutting long values on their own. Slack shows the whole prompt beside the card. Approving runs the tool again from its first line with the caller's identity. The approval also covers the caller's later calls on any account until anyone other than the caller sends a message, and the prompt says so; approving a request after someone else's newer message covers only that call. The caller's next message also releases their identity. Local subagents and remote agents that forward the caller honor the approval as of the call; token and connection calls in a workflow tool's own code don't. `openCodeChannel()` asks the same way, and so do creating a dynamic schedule or replacing its payload and starting an MCP event watch, whose work later runs as the caller. Where eve can't ask, a token or connection call fails with `ConnectionAuthorizationFailedError` and `reason: "confirmation_required"`, and a remote agent call fails with a terminal error.

**Acting for someone else.** `ctx.getToken(provider, { as })` and `ctx.requireAuth(provider, { as })` read the token of another person who has spoken in the session, named by `principalId`. eve hands it out when that person sent the latest message or approves the call, and otherwise asks them, signing them in if needed. The result's `principal` names who eve resolved. A name that matches no one fails with `reason: "principal_not_found"`, and one that matches two people fails with `reason: "principal_ambiguous"`. eve keeps a person's identity but not their attributes. With user tokens, the git extension's `gh` tool takes an `actor` input and passes it as `as`.

**Role checks.** A tool, a dynamic tool, subagent, or connection, or a credential your code picks that decides from `ctx.session.auth.current` alone gives the caller's access to anyone steering the turn; check `ctx.session.auth.sender` as well. Or use the new `steered()` approval policy from `eve/tools/approval`: set on a tool or as `approval` in `agent.ts`, it asks the caller before a call made after someone else spoke, with the same request, standing approval, and refusal as a call that uses the caller's identity, and never asks in a session with one person. eve's own checks do: the `gh` tool with app tokens and deployed self-modification call `authorize` for both people and need both to pass.
