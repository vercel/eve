# 전자약정 대시보드(모두싸인) 벤치마크 분석 및 로싸인 이식 기획

> 근거 자료: 고객 제공 벤치마크 PDF 26페이지(2종 동일본) + 화면 캡처.
> 목적: ① 벤치마크가 **왜 그렇게 설계되었는지** 구조적으로 해석하고
> ② 그 구조를 로싸인에 **누락 없이 이식**하는 페이즈 계획과 실행 결과를 기록한다.

---

## 1. 화면별 구조 분석 — 무엇이, 왜 이렇게 설계되었나

### 1.1 정보 구조(IA): GNB 3탭 + 컨텍스트 LNB

- 상단 GNB는 **홈 / 서명 요청 / 문서함** 3개 탭으로 고정 — 실무자의 업무는 "확인(홈) → 발송(서명 요청) → 관리(문서함)" 3개 동선으로 완결되기 때문.
- 좌측 LNB는 현재 탭에 **종속된 컨텍스트 메뉴**로 매번 내용이 바뀐다. 문서함에서는 상태 폴더,
  서명 요청에서는 요청 방식·도구가 나온다. 전역 메뉴와 문맥 메뉴를 분리해 화면당 선택지를 7±2개 이내로 유지하는 설계.
- LNB 최상단에 노란 **[서명 요청 시작하기]** CTA + **잔여 1,836건** 쿼터 바 — 과금 단위(발송 건수)를
  항상 노출해 사용량 인지와 업셀을 동시에 해결하는 B2B SaaS 패턴.

### 1.2 문서함: 상태 폴더 = 업무 큐(Queue)

LNB 폴더가 단순 필터가 아니라 **작업 대기열**로 설계되어 있다:

| 그룹 | 폴더 | 설계 의도 |
|---|---|---|
| (루트) | 모든 상태 | 전수 검색 기점 |
| 진행 중 | 내 서명 필요 / 상대 서명 대기 중 / 내 열람 필요 / 상대 열람 필요 | "누가 다음 행동을 해야 하는가"로 분류 — 책임 주체 기준. 서명과 열람(내용 확인만 요구)을 별도 요청 유형으로 구분 |
| 종결됨 | 서명 완료됨 / 열람 완료됨 / 서명 거절됨 / 서명 취소됨 / 요청 취소됨 | 종결 사유를 세분해 분쟁 시 이력 추적 가능 |
| 요청 전 | 작성 중 / 수정 중 / 예약됨 | 발송 전 문서의 생애주기. 임시 저장은 "22일 후 삭제 예정"으로 저장소 정리 자동화 |
| 문서 관리 | 데이터 추출 / 리마인더 | 목록이 아닌 **동작**. 데이터 추출=CSV 내보내기, 리마인더=날짜 기반 알림 큐 |

- 테이블 알고리즘: 기본 정렬 **마지막 활동일 ↓** (가장 최근에 움직인 계약이 가장 급한 계약이라는 가정),
  `10개씩 보기` 페이지네이션, 행 구성 = 체크박스·상태 뱃지·제목+서명자 서브라인·라벨·공유됨·요청일·체결일·마지막 활동일·추가 메뉴.
- 필터 바: 검색 기준 선택(제목▾) + 검색어 + 마지막 활동일 date-range + 라벨 + 공유 범위 + 숨긴 문서 제외.
  모든 필터는 폴더와 **AND 결합** — 폴더로 큐를 좁히고 필터로 정밀 조회하는 2단 탐색.
- 빈 폴더는 "'수정 중' 상태의 문서가 없습니다 + **모든 문서로 돌아가기**" — 막다른 화면을 만들지 않는 탈출구 규칙.

### 1.3 리마인더: 날짜 중심의 알림 큐

"안녕하세요 ○○님, **오늘의 알림이 N건** 있습니다" 헤더 + 기간 칩(오늘/이번주/다음주/이번달/전체) +
[+ 알림 추가하기]. 문서가 아니라 **날짜가 1차 축** — 계약 실무는 기한 관리 업무라는 통찰. (→ 로싸인 캘린더 뷰·리마인더 폴더의 근거)

### 1.4 서명 요청: 방식 선택 → 업로드 → 3단계 위저드

- **방식 선택**: 기본(단건 요청) / 고급(대량전송 = 동일 양식 다수 일괄, 링크서명 = 서명자 미지정 링크 수집).
  요청의 카디널리티(1문서:N서명자 / N문서:N서명자 / 1문서:불특정)에 따라 플로우 자체를 분기.
- **문서 업로드**: 드래그 앤 드롭 + 파일 제한 명시(PDF 10MB, HWP·DOCX 등 5MB) + **준비된 템플릿으로 시작**
  (템플릿마다 열람/서명 유형 뱃지). 업로드가 부담스러운 사용자를 템플릿으로 우회시키는 이중 진입점.
- **1단계 서명자**: `계약 서명 요청 | 문서 열람 요청` 탭, `순서대로 한 명씩 / 순서없이` 라디오,
  서명자 카드(이름 + 채널 선택: **이메일/카카오톡/대면서명** + 알림 언어 ko), 재정렬 핸들(▲≡▼),
  **서명자 추가하기 (n/30)** 대형 버튼, 빈 서명자 카드 모두 삭제.
- **2단계 입력**: 서명자별 아코디언 + `기본 | 자동 입력` 탭. 도구 = 사인·도장 / 텍스트 / 체크박스 /
  서명한 날짜 / 날짜 / 드롭다운 / 이미지 / 첨부파일 요청. 우측 페이지 썸네일, 상단 undo·redo·zoom.
  자동 입력은 서명 시점에 시스템이 채우는 필드(이름·일시 등)로 입력 오류를 구조적으로 제거.
- **3단계 기타**: 카드 스택 = 문서 제목·서명 기한(14일)·완료된 문서 잠금·전송 예약 / 첨부파일 /
  외부 참조자 / 계약 리마인더(설정 N) / 서명자별 남길 말·인증 수단 추가. 우하단 **내부결재 진행**(발송 전 사내 승인 훅).
- 전 단계 공통: 상단 스테퍼(1 서명자 › 2 입력 › 3 기타) + 우상단 **임시저장** 인디케이터(자동 저장).

### 1.5 홈: 진행 현황(기간 선택) + 알아보기 + 소식

숫자 4종(내 서명 필요/상대 서명 필요/서명 완료/예약 중) + 온보딩 링크 + 제품 소식. 숫자를 클릭 동선으로 잇지 못한 점이 약점 (→ 로싸인은 카드 클릭 시 해당 폴더로 이동 + 추이 차트 + 독촉 위젯으로 보강).

## 2. 로싸인 이식 계획 및 실행 결과 (페이즈별)

> 프로덕션 스택은 고객 환경 메모 기준 Next.js(App Router)+React+Tailwind / FastAPI를 권장하며,
> 본 프로토타입은 동일 IA·인터랙션을 의존성 0의 SPA로 선구현했다.

### Phase M1 — 메일함 전환 + 폴더 레일 (벤치마크 LNB 이식) ✅

- 문서함 → **메일함**: Gmail형 행(아바타·굵은 미확인 행·스니펫에 요청일/체결일/라벨/기한) + 호버 시
  **✉️ Gmail 발신 / 💬 카카오 알림 / ⋮ 이력** 퀵 액션.
- 폴더 레일: 전체 문서함 / 진행 중(내 서명 필요·상대 서명 대기) / 종결됨(서명 완료됨·**거절·취소됨**) /
  요청 전(작성 중·예약됨) / 문서 관리(**리마인더**·**데이터 추출**) — 폴더별 건수 뱃지, 리마인더는 경고 색.
- `10/25/50개씩 보기` 페이지네이션, 기간 필터(오늘/7일/30일), 빈 폴더 "모든 문서로 돌아가기".
- **데이터 추출** = 현재 필터 결과 CSV(UTF-8 BOM) 즉시 다운로드. LNB **잔여 1,836건** 쿼터 바.
- 발신 컴포즈 모달: 채널 토글(이메일 Gmail / 카카오 알림톡), 수신자 칩, 제목(이메일만)·본문 템플릿,
  연동 계정 표시. 발신 내역은 감사 로그(NOTIFY)에 기록.

### Phase M2 — 서명 요청 플로우 벤치마크 이식 ✅

- **요청 방식 화면**: 기본(단건 요청) / 고급(대량전송·링크서명) 카드.
- **문서 업로드 화면**: 드롭존 + 파일 제한 안내 + 준비된 템플릿 그리드(필드 사전 세팅 → 2단계 생략 가능).
- 1단계: 계약 서명/문서 열람 탭, 순서 라디오, 채널 선택(이메일/카카오톡/대면서명 — 대면은 연락처 생략),
  ▲▼ 재정렬, (n/30) 카운터, 빈 카드 일괄 삭제, 자동완성 유지.
- 2단계: `기본 | 자동 입력` 도구 탭. 기본 8종(+날짜/드롭다운/첨부파일 요청 추가), 자동 입력 3종(이름/일시/조직명).
- 3단계: 첨부파일 / 외부 참조자 / 계약 리마인더(기한 3일 전·1일 전·매일) / 남길 말 / 인증 수단
  (카카오 본인인증·휴대폰·공동인증서) 카드 스택 + 기존 발송 전 체크리스트 병행.
- **대량전송**: 템플릿 + 수신자 명단(이름,연락처 줄 단위) 파싱 → 일괄 큐 적재.
- **링크서명**: 템플릿 선택 → 서명 링크 생성 + 복사.

### Phase M3 — 캘린더 뷰 (리마인더의 날짜 축 확장) ✅

- 메일함 3번째 보기 모드: 월간 그리드에 일자별 **① 발송약정 ② 서명됨 ③ 서명대기** 숫자 칩.
- 날짜 클릭 → 해당 일자 문서 목록 모달(행에서 바로 발신 가능). 이전/다음 달 이동.
- Google Calendar 연동 설계: 서명 기한·예약 발송을 사용자 캘린더에 이벤트로 자동 등록(백엔드 OAuth 훅).

### Phase M4 — 검증·문서화 ✅

- 헤드리스 브라우저로 12개 시나리오(메일함 폴더 전환·페이지네이션·컴포즈 2채널 발신·칸반·캘린더 집계·
  방식 3종·업로드·자동입력 탭·3단계 카드·대량전송·링크 생성·모바일) 전부 통과, 콘솔 에러 0.
- 단일 파일 배포본 재생성, API 계약 갱신(`/notify`, 캘린더 집계, 대량전송·링크서명).

### 후속(프로덕션 이관 시)

- 내 열람/상대 열람 별도 폴더(열람 요청 데이터 축적 후), 서명 거절/취소/요청 취소 3분화,
  내부결재 라인 편집기, 다중 선택 일괄 액션, undo/redo·zoom 편집기 고도화, 숨긴 문서 처리.
